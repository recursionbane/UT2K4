# Native skeletal LOD profile

This authored cooker selects existing UT2004 skeletal render LODs and removes redundant per-LOD reimport arrays. It does not need a new runtime codec. Original game packages and the licensed native source used to check the format are not distributed with the tooling.

The default near detail is the first authored lower LOD with at most 40% of the original base face count; when none meets that threshold, the last smaller authored LOD is used. Existing lower render LODs remain available. A mesh with no smaller authored representation can retain its base render data while dropping redundant per-LOD import data. This deliberately lowers visual detail; it is not a perceptually lossless profile.

Compiled skinning streams, smooth/rigid vertex and index buffers, and render characteristics are copied from the selected authored LODs. Reference skeletons, attachment names/transforms, bone collision, physics references, materials, scale, bounds, and authentication data are preserved. Global `RawVerts`, `RawWedges`, `RawFaces` and related arrays remain intact: authentication routines can inspect their counts. The four per-LOD lazy arrays are described by the native serializer as conversion/update data; the native renderer uses the compiled streams instead. An editor or extractor that depends on those per-LOD arrays may need to rebuild them from the retained global source data.

`readUe2SkeletalLayout` checks the `UPrimitive` → `ULodMesh` → `USkeletalMesh` grammar and the `FStaticLODModel` records against package bounds, array dimensions and exact export end positions. The current supported profile is package versions 120–128 with internal mesh versions 2–4. Unknown or malformed meshes remain unchanged. Soft-section index ranges follow the native renderer's cumulative index cursor; their serialized `FirstIndex` can be uninitialized and is not interpreted as a rigid-section offset.

`cookSkeletalLods(source, {nearFaceRatio: 0.4})` returns a private rewritten buffer and changed ranges. The canonical export-table writer changes only the selected export sizes, retaining object identities and absolute object positions. Every retained `TLazyArray` absolute end pointer is relocated after compaction. The rest of each old export span is zero-filled; the package's native file extent remains unchanged. A strict reparse checks all pointers, and byte comparisons protect global raw data, collision, skeleton/attachments, compiled selected LOD data and every unrelated export, including animation sequences/events.

A transport caller must bind the source package/index hashes, reject overlap with existing codec regions, reframe the new skeleton, preserve current region descriptors and accept only a smaller complete transport plus index. Cached results may be reused only on exact source matches. A later StaticMesh, Model, audio or texture rewrite requires a fresh source check and, when necessary, recooking; independently measured savings must not simply be added.

The grammar was checked against the owned native `UnSkeletalMesh.h`, `UnSkeletalMesh.cpp`, `UnLodMesh.cpp`, `UnRenderUtil.cpp` and `UnTemplate.h` serializers, with UEViewer as a secondary cross-check. UEViewer's reconstruction path can require the omitted per-LOD import arrays even though the native renderer does not. Synthetic tests contain authored data only and cover canonical sizes, absolute-pointer relocation, soft-index sentinels, auth/bone/collision preservation, and rejection of corrupt or unknown layouts. Representative native player/weapon testing is recorded separately from structural corpus validation; neither establishes full-corpus visual quality.
