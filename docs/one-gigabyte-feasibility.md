# One-gigabyte deployment trial

The working target is 1,000,000,000 bytes for a self-contained deployment containing all 861 maps and all 271 music tracks. The engine, protected shell, codecs, indexes, encrypted payloads and any required fallback files count toward it. The active game-data inventory measured 3,350,065,331 bytes before this experiment. The existing sealed Pages directory measured 22,935,255,282 bytes including historical ciphertext. The current routing index references 11.397 GB of ciphertext, leaving 11.531 GB of historical ciphertext outside the current index. Repacking the audit’s compact route set would require 3.396 GB of plaintext files before encryption, including shell and selected HTTP variants, conditional on explicitly supporting operation without whole-original fallbacks. Preserving those fallback routes brings the corresponding file set to 10.383 GB. The compact route set plus the staged music saving projects to about 3.233 GB before final envelope/index costs.

## What actually runs

The isolated native Vorbis candidate converts 256 tracks to mono quality −1 at their original sample rates with a 5 kHz frequency cutoff. The remaining 15 use the current representations. The 271-track transport costs **204,115,246 bytes**, down from 367,196,319. Converted files passed sample-count and original-comment/loop metadata checks. A native menu-to-Rankin run fetched the expected hashes and produced OpenAL output for both tracks. The cutoff audibly reduces high frequencies. A separate 2 kHz trial gives about 151 MB of native files with substantially less treble.

After the 5 kHz change, the active game-data subtotal is **3,186,984,258 bytes**, leaving **2,186,984,258 bytes** to remove before accounting for the shell. The 1 GB budget gives all non-music content, the runtime and packaging at most **795,884,754 bytes**. The current non-music game-data subtotal is 2,982,869,012 bytes. Reaching that allowance requires at least 73.3% further reduction there.

## Where a rewrite would have to pay off

Map package bases occupy 1,720,023,813 bytes. I sampled 24 maps, taking one midpoint from each equal-sized group of the 861 maps ranked by current package size. Their current bases total 46.70 MB. Recompressing each complete current skeleton as a single Zstd stream takes 42.09 MB. As a diagnostic, zeroing all parsed Model lightmap sections and native render geometry cache sections lowers that to 27.91 MB. Those zeroed files are unusable. The experiment measures the aggregate influence of these fields while showing how much remains even if replacement lighting and render caches cost nothing. Shared encoded payloads are outside those numbers.

The first functional Rankin data conversion preserves the original BSP collision and topology while packing a separate render vertex representation. The map's current frames and index take 1,758,256 bytes. The candidate's frames, index and new payload take 1,732,114 bytes, with a further 3,924 bytes for the shared decoder. The local native run reached an owned Rankin pawn and completed the gameplay smoke test. Hash checks matched all 707,008 canonical BSP/collision-span bytes in the comparison. That particular precision reduction is too small to justify a full-corpus rollout on budget grounds.

A 1 GB edition needs a different way to represent both maps and shared art. A meaningful next milestone would exercise a compact map, materials, animated player, collision, weapons and audio together on an indoor map and an outdoor terrain map. Count the complete shared and per-map costs before extrapolating and compare play and appearance against the source. A complete build must also pass a clean-directory byte count and an offline request audit that accounts for every runtime dependency.

The native music trial, feasibility arithmetic and map diagnostics are retained locally under `.local-runtime/budget-300-music/`; the playable music stage and its native proof are in `.local-runtime/budget-music5k-stage/` and `.local-runtime/budget-music5k-native-proof/`.
